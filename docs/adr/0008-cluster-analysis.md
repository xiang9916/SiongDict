# 聚类分析：按义项比较方言点

**状态**：已采纳（2026-11-19）；2026-11-20 起相似度改为 λ=2 收缩平均、界面改为全屏页；2026-11-20 起「自動」分群改为候选分區搜索（UPGMA 各 k + Louvain 多解析度）后按轮廓系数挑，模组度降为对照，并新增地图展示（见下、ADR-0010）
**相关**：ADR-0005（入组硬规则）、ADR-0006（数据层端口）、ADR-0007（方言范围与筛选树）、`AGENTS.md` §2／§5.1

## 背景

同源词库现有 206 组、2,804 条人工条目（全部 `source='manual'`），覆盖 383 个方言点；字音库 `info` 表共 491 个方言点。这批条目的价值在跨方言对照：一个义项在哪些点有同源词、这些点彼此共享多少义项，直接反映词汇层面的亲疏。但既有的「搜同源」只能逐组看卡片，没有整体视图，判断「某片方言与哪片更近」只能人眼比对。

需求是在 App 内新增「聚类分析」：把方言点按同源词相似度聚成若干类，并画成可交互的散点图。约束是离线、客户端计算、结果可解释、同一份资料每次结果一致（便于讨论与回归）。它因此挂在独立的「研究」入口下，而不是检索模式。

## 决定

### 1. 相似度以义项（`semantic_tag`）为单位

- 义项 = `cognates.semantic_tag`（如 `Press`、`Hide`）；一个义项下挂多个音类组是正常结构（见 ADR-0005、`AGENTS.md` §5）。
- 对任意两点 A、B：T = 两点都收录的共同义项集合。在每个共同义项下，两点共享至少一个 `cognate_group` 记 +1，都收录但组不相交记 −1，只有一方收录该义项则不计入 T。
- 相似度用**收缩平均**：s = 计分总和 / (|T| + λ)，λ = 2；距离 d = (1 − s) / 2。|T| = 0 时 s = 0、d = 0.5（没有可比证据放在中点，而不是判为最远）；对角 d = 0。s 的理论值域是 (−1, 1)。
- λ 的作用是把「证据少」的噪声压下去：20 个共同义项全共享 → 20/22 ≈ 0.909，10/10 → 10/12 ≈ 0.833，3/3 → 3/5 = 0.600，1/1 → 1/3 ≈ 0.333——同样是「全部共享」，共同义项越多，相似度越接近 1，即**共同义项越多越可信**。λ = 2 相当于先验 2 个「中性」义项；取 2 是经验值（λ=1 时 1/1 = 0.5 太乐观，λ 更大则收缩过强），不随资料规模自适应。
- 理由：语义标签是现成且经人工核过的证据（新增条目必须注释语义相符）；按义项计分能区分「收 10 个义项只共享 1 个」与「收 2 个共享 2 个」；缺义项不计入而非记 −1，避免收录少的点因覆盖面小而相似度被压得过低。

### 2. 「自動」分群 = 候选分區搜索后按轮廓系数挑，模组度只作对照

- 先试的是 `averageLinkage`（UPGMA）+ 轮廓系数选 k：自底向上合并平均距离最近的两簇，距离平手按「两簇最小成员索引」字典序决定；记录 k = 2..min(10, n−1) 的全部分区，用原始距离矩阵算平均轮廓系数（单点簇记 0），最优分类数取轮廓系数最大者、平手取较小 k。
- 这条路在真实数据上长期退化到 k = 2：382 点里 58.7% 的点对没有共同义项、距离被锁在 0.5，最优分区退化成「一类 370 点、一类 12 点」，平均轮廓系数只有 0.2075——数值不低，但没有把点分开，信息量为零。
- 第二轮改成「纯 Louvain、按模组度选」：2026-11-20 仪器化实测一層 4 类、Q ≈ 0.2841（183/115/37/48）。Q 看着漂亮，但**按 Q 最大选分类数会退化成粗切**（模组度对「两簇大块」几乎单调），同样不能回答「该分几类」。两次失败指向同一个结论：不要用单一准则直接定 k。
- 现方案（`analysis/PartitionSearch.kt`）是**先造候选池，再用轮廓系数挑**：候选 = UPGMA 各 k（2..min(10, n−1)）的分区 + 确定性 Louvain 在分辨率 γ 网格 `GAMMA_GRID`（0.25／0.5／0.75／1.0／1.25／1.5／2.0／2.5／3.0／4.0，共 10 档，边权 = 相似度、局部移动与聚合 ≤ 3 层、模组度增益 < 1e-9 停、每层最多 100 轮扫描、全程无随机数）上的分区，并对每个 k 再二分 γ 6 步细化（`BISECTION_STEPS = 6`）；**每个 k 只保留轮廓系数最高的候选**（平手优先 Louvain、再取小 γ），候选池按 k 升序。
- 「自動」值 = 候选池里**每个簇都不小于 `minClusterSize(n) = max(2, ⌈5%n⌉)`**（`MIN_CLUSTER_FLOOR = 2`、`MIN_CLUSTER_SHARE = 0.05`）的候选中轮廓系数最高者，平手小 k → Louvain → 小 γ；没有合格候选时退回全体候选的轮廓最优。5% 下限是为了挡掉「切出一个 2 点簇把轮廓系数抬高」的小把戏。
- 稀疏判定改为**轮廓系数 < 0.10**（`ClusterAnalysisResult.SPARSE_SILHOUETTE`），全屏页红字提示「分群結構偏弱（輪廓係數 < 0.10），結果僅供參考。」；0.10 是经验阈值，不是统计保证。
- 模组度 Q 仍然计算并展示（`modularity`，按自动分区的标签、resolution = 1 计算），但**只作对照**，不参与任何选择：它回答「这批数据有没有社群结构」，不回答「该分几类」。
- UPGMA 与 Louvain 分区都留在候选池里：分类数滑桿要能手动覆盖自動值，需要在固定 k 下取分区；k 上限 10——再多的类别在手机散点图上已无法辨识，也容易把稀疏数据过拟合。

### 3. 确定性三维力导向布局，不用随机降维

- 初始位置固定在半径 0.4、球心 (0.5, 0.5, 0.5) 的球面上，用 Fibonacci 球面均匀撒点（第 i 点：t = (i + 0.5)/n、φ = acos(1 − 2t)、θ = π(1 + √5)i）；不用圆周等角点——圆周初值会让布局长期挤在平面附近，看不出三维结构。
- 200 轮迭代：O(n²) 斥力（∝ 1/d²）+ 每点连向正相似度最高的 8 个邻点作弹簧（权重 s = 1 − 2d、自然长度 0.32）+ 向立方体中心 (0.5, 0.5, 0.5) 的向心力；步长随轮次冷却，最后按三轴最大跨度等比缩放到 [0,1]³。
- 全程不用随机数：同一份距离矩阵永远得到同一组坐标，便于截图对比与问题复现。
- 布局只决定「画在哪里」，不参与聚类；聚类结论由社群偵測（或用户指定的 k）决定。
- 分群锚点布局：聚类给出类号后，把同类点从纯力导向位置收缩到 Fibonacci 球面锚点附近（`groupedLayout3D(points, labels)`：类号升序去重后按 `anchorRadius = 0.35` 均布锚点、类内按质心收缩 `spread = 0.35`，再归一化到 [0,1]³）；类号顺序固定，同一分区必得同一布局，类内相对形状保留力导向结果。切换分类数时画布用 700ms 补间（`lerpLayout(from, to, t)`，缺一侧的点按存在侧取值）把点从旧坐标聚拢到新坐标，只重算分区与布局、不重跑聚类。

### 4. 三维可视化：透视投影、手势与标签

- 投影：相机置于 z 轴正方向、距立方体中心 2.8（归一化单位），焦距 1.6；先把 [0,1]³ 坐标平移到立方体中心，再绕 Y 轴转 yaw、绕 X 轴转 pitch，最后按 scale = focal / (distance − z) 做透视除法。归一化坐标旋转后 z ∈ [−0.87, 0.87]，分母恒 ≥ 1.93，不会除零。
- 默认视角 yaw −24°、pitch 18°（略侧转 + 俯视，一眼看出立体感）；pitch 限制在 ±80°，避免翻到背面导致上下颠倒；缩放范围 0.6–4 倍。
- 手势：单指拖动 = 旋转（左右改 yaw、上下改 pitch，pitch 夹在 ±80°）；双指 = 缩放 + 平移；双击复位到默认视角与 1 倍缩放。手势只改相机参数，不重算布局、不重跑聚类。
- 标签默认显示：可见点 ≤ 40 时全显；否则按深度从近到远排序后贪心放置，与已放置标签的屏幕矩形相交就跳过，上限 80 个——保证近处标签不被远处糊住。选中点始终显示标签。
- 投影是纯函数（`ui/ClusterProjection.kt`，6 项 JVM 测试覆盖旋转、透视、边界与俯仰夹角），Compose 画布只负责绘制；因此同一资料、同一视角的截图可以逐像素复现。
- 聚拢动画：切换分类数（或重算后布局变化）时，`ClusterMap` 保留上一帧坐标，用 `animate` + `tween(700ms, FastOutSlowInEasing)` 驱动 `lerpLayout` 插值，点、连线、凸包、标签全部用插值后的坐标绘制；动画只改绘制坐标，不触发重新聚类，因此滑桿拖动时不会卡在计算上。
- 为什么还要「确定性」：三维图一旦带随机初始旋转或抖动，讨论时没法指着同一张图说话；这里所有相机参数、锚点、初始分布与插值终点都由手势与常量决定，没有随机数。

### 5. 全部在客户端计算，数据层只加两个只读查询

- `Lexicon.dialectProfiles()`：读 `info` 表的 簡稱／音典分區／音典顏色／音典排序／經緯度，按 (音典排序, 簡稱) 排序，共 491 点（經緯度 491/491 有效，供地图页使用）；空白簡稱跳过，分区与颜色允许空串，与「方言筛选树」共用同一次 generation 缓存。
- `CognateBook.memberships()`：读 `cognates` 的 lang／cognate_group／semantic_tag，共 2,804 条；同源词库缺失时返回空列表，与「搜同源」一致地降级。
- ViewModel 首次打开时读一次、存成内存快照；调整分类数只切换分区，调整最小义项数只用快照重算，均不再读库；重置数据库时作废快照并关闭全屏页。慢结果用代际编号（`clusterSeq`）守卫，不覆盖新参数的结果。
- 复杂度 O(n² + 成员条数)，n 为参与聚类的点数（有同源词的点 383）；单次计算在手机端是毫秒到百毫秒级。

### 6. 聚类范围 = 当地方言筛选树可见点，再按证据量排除

- 输入先按**当地方言筛选树**切片：`DialectFilters.selected == null` 时全收；否则只留 `leafKey(division)` 命中的点，与检索的方言筛选同一套前三段分区叶子键。
- 切片后再排除：没有同源词成员的点（`excludedNoCognates`）、义项数低于「最小义项数」的点（`excludedSparse`）。
- 全屏页摘要只保留一行「模組度 · 輪廓係數」（旧的三行摘要已删除）；排除明细改由日志（`Log.i("ClusterTest", …)`）与图例呈现，避免头部信息过量。
- 「最小义项数」的**默认值由数据决定**：在 1..上限 内逐个门槛试算「自动分群」的轮廓系数，取最大者（平手取小）。该搜索只跑粗候选池（γ 网格 + UPGMA，不做每 k 的二分细化）以控制开启延迟；正式 `analyze` 仍二分细化，实际轮廓系数只会 ≥ 估计值（2026-11-20 实测两者挑出的门槛与数值一致）。轮廓系数对小样本天然偏大，所以候选门槛另加**覆盖率下限**——参与点数不得少于有同源词点数的 50%（至少 2 点），否则真实库会一路挑到只剩 10 个点的门槛（2026-11-20 实测：不设限时最大值落在门槛 24／10 点）。加下限后真实库默认门槛 4：209/383 点参与，491 点中 108 点无同源词、174 点因义项不足被排除（2026-11-20 仪器化实测：该门槛下自动 k = 2、规模 178/31、轮廓 0.1972）。
- 关闭全屏页期间改方言筛选不会触发计算；下次打开时按当时的筛选状态重新切片，仍复用已读入的快照，不重读库。
- 理由：聚类的对照基准应与使用者当前关心的方言范围一致；但图不能「悄悄少点」，所以排除计数必须显性可见。

### 7. 颜色分两套：节点用音典颜色，类别用固定调色盘

- 节点颜色取 `info.音典顏色`，支持 `#RRGGBB`、`#AARRGGBB` 与「逗号分隔双色」（半角或全角逗号，画成线性渐变）；解析失败回灰色。
- 类别颜色用固定 10 色调色盘，按类别序号取模，只用于凸包填色、虚线与图例。
- 两套颜色不混用：节点颜色表达「这是哪个方言点」（与检索卡片一致），类别表达「聚类把它分到哪一类」。

### 8. 地图展示（见 ADR-0010）

- 全屏页「在地圖展示」按钮（`cluster_map_open`）→ `ui/ClusterMapScreen.kt`（`cluster_map_screen`）+ `ui/GeoMapView.kt`：离线省界底图上按站点经纬度画泰森多边形与点位，只画参与聚类的点；返回键先退地图、再退聚类页。
- 底图来源与授权、Web Mercator 投影与视图变换、泰森多边形裁剪、手势与标签开关、底图缺失时的降级，全部见 **ADR-0010**。本文只记一条界限：分区与颜色由聚类结果决定，地图只换一种投影方式看同一份分区，不重新聚类。

## 数字

- 同源词：206 组 / 2,804 条（全部 manual），覆盖 383 个方言点、140 个义项。
- 方言点：491 个（`info` 表）。
- 默认参数（`minTags` 自动）：默认门槛 4 → 209 点参与、108 点无同源词被排除、174 点因义项不足被排除（2026-11-20 实测）；手动滑到 1 时 383 点全参与。
- 义项数分布：1 个义项 81 点、2 个 67 点、3 个 27 点、4 个 30 点、5 个 25 点……最多 66 个（道縣梅花）。
- 分类数：「自動」值 = 候选池里每簇 ≥ max(2, ⌈5%n⌉) 的候选中轮廓系数最高者。**2026-11-20 仪器化实测**：门槛 1（383 点）→ **k = 6**、类别规模 **61/108/75/62/31/46**、轮廓 **0.1587**、Q ≈ 0.2723（仅对照）；默认门槛 4（209 点）→ **k = 2**、规模 **178/31**、轮廓 **0.1972**、Q ≈ 0.0997（仅对照），义项不足排除 174 点。上一轮（λ=2、2,804 条／206 组、无候选池）实测为门槛 1 → 4 类（183/115/37/48、Q ≈ 0.2896）、默认门槛 4 → 3 类（Q ≈ 0.1885），已作废，仅作历史记录。`clusterAnalysisUsesCommunityDetection` 的 `Log.i("ClusterTest", …)` 日志可复核；手动可选 k = 2..min(10, n−1)；最小义项数滑桿范围 1..min(10, 快照中最大义项数)。
- 相似度收缩：λ = 2（s = 总分/(|T|+λ)，s ∈ (−1,1)）。
- 稀疏阈值：轮廓系数 < 0.10；模组度只作对照（不再用 0.15 判定）。
- 候选池参数：Louvain γ 网格 0.25–4（10 档）、每 k 二分 γ 6 步、簇下限 max(2, ⌈5%n⌉)（5% 且至少 2 点）、每 k 只留轮廓最高者。
- 布局参数：三维，200 轮、斥力系数 0.0025、每点 8 邻弹簧（0.8，自然长度 0.32）、向心 0.02、Fibonacci 球面初值（半径 0.4）、归一化到 [0,1]³。
- 投影参数：相机距离 2.8、焦距 1.6、默认 yaw −24° / pitch 18°、pitch 限 ±80°、缩放 0.6–4。

## 考虑过的方案

- **按 IPA 读音相似度聚类**：需要音类对齐、韵母归并和权重设计，且同源词库已有更硬的人工语义标注；音近不等于词同源，会引入新的判断错误。否决。
- **把计算放到数据库外部／云端**：本 App 除「檢查更新」外离线，加服务端会让单机可用性失效。否决。
- **随机 t-SNE／UMAP 降维**：结果依赖随机种子与超参数，同一资料每次图形不同，难以讨论与回归；样本只有几百点，收益有限。否决。
- **谱系树／树状图展示**：手机上可读性差，用户要看的是「哪些点聚在一起」而不是合并顺序；社群分区 + 三维散点图已经够用。否决。
- **k-means**：需要预设 k，对非球形簇与稀疏数据不稳定，也没有现成的自动选 k 方案。否决。
- **只按模组度 Q 最大自动选 k**：实测 Q 对「两簇大块」几乎单调，选出来不是 k = 2 就是 k = 3，等于没回答「该分几类」。否决，Q 保留作对照指标。
- **相似度按读音条数或同音字组数加权**：那衡量的是资料量而非同源关系，会让收录多的点天然相似。否决。

## 后果与限制

- O(n²) 的距离矩阵与斥力计算：383 点约 14.7 万对、200 轮约 2.9×10⁷ 次运算，手机端可接受；若同源词覆盖大幅增加（上千点），需改用网格近似、抽样或预计算。
- 手动分类数上限 10；n < 3 时不分区（`optimalK = 1`）；单点簇轮廓系数记 0，n 很小时对照分数可能偏低。候选池要跑 UPGMA 各 k 与 Louvain 多档 γ，计算量约为单次聚类的数倍（仍毫秒到百毫秒级）；Louvain 层数 ≤ 3。
- 「共同义项下无共享组记 −1」是强惩罚：语义标签相同但音类组对不上会被明显拉远，这是有意为之（宁可分开，也不同源错并）。
- 稀疏提示只是经验阈值（轮廓系数 0.10）；轮廓系数对非凸簇与锁死在 0.5 的距离并不敏感，所以它只用于在候选池里排序，不当作统计保证；模组度只作对照。
- 聚类输入不随检索词变化，避免「搜一个字就看到一张图」的误导；方言范围只由筛选树决定。
- 新增两个数据端口方法属只读扩展；`AGENTS.md` §2 文件树与 §5.1 数据流同步更新。
- 首版不含图片／CSV 导出与自定义算法参数，不阻塞发布。

## 实施

- 算法：`app/src/main/java/org/siongdict/app/analysis/` 十个纯 Kotlin 文件——`ClusterModels.kt`、`Similarity.kt`、`HierarchicalClustering.kt`（UPGMA）、`CommunityDetection.kt`（确定性 Louvain）、`PartitionSearch.kt`（候选池与自動挑选）、`ClusterLayout.kt`、`ClusterEngine.kt`、`MapModels.kt`、`MapProjection.kt`（Web Mercator）、`Voronoi.kt`（泰森多边形），不依赖 Android，可直接 JVM 测试。
- 界面：`ui/ResearchDialog.kt`（「研究」一级入口，白底 Dialog + 右上「關閉」）、`ui/ClusterAnalysisScreen.kt`（全屏页，不套 Dialog；一行摘要、参数、图例、选中点详情、在地圖展示入口）、`ui/ClusterMap.kt`（透视投影画布、凸包、连线、旋转／缩放／平移手势、标签、点选）、`ui/ClusterProjection.kt`（3D 透视投影纯函数）、`ui/ClusterMapScreen.kt` 与 `ui/GeoMapView.kt`（地图页，见 ADR-0010）、`ui/ClusterColors.kt`（调色盘与颜色解析）、`ui/SearchViewModel.kt`（快照、筛选切片、代际守卫）、`ui/SearchScreen.kt`（入口装配）。
- 数据：`data/Models.kt`（`DialectProfile` 含经纬度、`CognateMembership`）、`Lexicon.dialectProfiles()`、`CognateBook.memberships()`、`data/MapAssets.kt`（离线底图读取，坏档回空表）。
