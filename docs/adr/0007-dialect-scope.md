# 方言范围：湖南全省 + 湘语相关分区 + 江西萍乡市

**状态**：已采纳（2026-11-16）
**相关**：ADR-0005（同源词入组规则）、`AGENTS.md` §5、`tools/build_db.py`

## 背景

`tools/build_db.py` 自建库起用两道筛选条件从 MCPDict 中取点：`matches_fq()`（《中国语言地图集》第二版「湘语」分区，或音典分区命中湘赣／湘南／道州／乡话等关键词）与 `matches_geo()`（仅收湖南省）。结果：488 点、604,504 条读音、123,898 组同音字（2026-11-16 前实测，md5 `78af6bc3186abcf017d821b30975e80f`）。

问题：江西萍乡市与湘赣片毗邻。MCPDict 中萍乡市 6 点里，蓮花／蓮花坊樓／蓮花閃石 已因音典分区（湘贛）命中入库；蘆溪、萍鄉、上栗 3 点因行政上不属湖南被 `matches_geo()` 挡掉，但 3 点的音典分区均为「湘贛－贛西－袁州」，与既有岳州／北湘／雪峰／羅霄／南湘同属湘赣大区。用户 2026-11-16 裁决（m02293）：siongdict 范围加入江西萍乡市。

## 决定

在「湖南全省」之外，收入 MCPDict 中「省=江西 且 市以萍鄉开头」的全部点。`matches_geo()` 改为：

```python
EXTRA_GEO = (("江西", "萍鄉"),)


def matches_geo(d):
    prov = d.get("省", "").strip("*")
    if prov == "湖南":
        return True
    city = d.get("市", "").strip("*")
    return any(prov == p and city.startswith(c) for p, c in EXTRA_GEO)
```

最终收录范围仍是三条件并集：① 音典分区命中湘赣等相关分区；② 地图集二湘语片；③ 湖南全省 + 江西萍乡市。前两条未改，第三条只增加一个省外行政市。

## 考虑过的方案

- **保持只收湖南**：萍乡 3 点与湘赣同片，用户研究需要；否决。
- **收整个江西省**：超出「湘语相关」范围，会把非湘赣点带入；否决。
- **只按音典分区「湘贛－贛西－袁州」全收**：与本批 3 点实际重合，但以行政市为界更可解释、也便于向上游说明范围；否决该实现方式，保留行政市规则。
- **手工把 3 点补进现有库**：不可重复，上游重建即丢；否决。

## 后果

- 数据规模：488→491 点、604,504→609,323 条读音、123,898→124,577 组同音字。`cognates.db` 的库存变化来自同批 T2 写库（29 条 / 4 新组 / GetWet 改名），与本次重建无直接关系。
- **发版必须 bump `versionName`**（目标 0.4-rc.15 / versionCode 49）：`DatabaseFiles.isOutdated()` 以 `versionName` 不等比较作为重拷 assets 的唯一开关；资料变了不 bump，既有使用者永远留在旧库（AGENTS.md §6）。
- App 的方言筛选树按 `info.音典分區` 动态生成，新增「湘贛－贛西－袁州」路径无需代码改动即可出现（T3 的三层树／四层归并规则）。
- 测试：`DataLayerTest` 的库存与萍鄉断言（T5）、JVM 28 项（T3 + 既有 24）与仪器化 19 项（T5）同步更新；`cognateInventoryMatchesRelease` 的旧数字须一并改。
- 上游 MCPDict 再变时，萍乡 3 点若消失／改名，同源词按「字组＋读音＋方言点」唯一匹配会失效，须人工检查引用（AGENTS.md §5）。
