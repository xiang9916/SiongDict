# 简体渲染只在显示层做，字表随包分发

「關於」面板需要一個開關「渲染為簡體中文 (Beta)」：打開後所見文本轉簡體，默認關閉，狀態持久化。

決定：轉換只發生在**顯示層**——界面與導出共用 `Simplifier.display()`；數據庫、檢索行為、`字組` 與使用者輸入一律不動。轉換表隨包分發在 `app/src/main/assets/t2s.json`（OpenCC 的 `TSPhrases` 例外表 + `TSCharacters` 字表，另疊一層本地「著」保護詞表），由 `tools/build_simplifier.py` 生成。開關存 `siongdict_prefs` 的 `render_simplified`，`重置資料庫` 不會重置它。

為什麼：① 數據庫是上游 MCPDict 的重投影，任何就地轉換都會被下一次 `build_db.py` 重建沖掉；② 檢索依賴繁簡異體混搜（見 ADR‑0002），把數據固化成單一寫法反而削弱它；③ `字組` 是字形本體，`隻/只`、`乾/干` 一轉就看不出原貌。

## Considered Options

- **在建庫時多存一份簡體列**：不可逆，且上游重建即失效。
- **運行時引入轉換庫或算法**：App 要離線，代價比一張 56 KB 的表更大。

## Consequences

關掉開關即回到原樣，數據零殘留；導出與屏幕一致（同一個函數）。轉換質量取決於表：`著→着` 是本地啟發式（默認轉，讀 zhù 的詞靠保護表按住）；IPA、數字、英文、Markdown 結構字符不參與轉換。缺表時渲染退化成 no-op（只記一條 warn，不崩）。新增的資源與構建步驟已寫進 AGENTS.md §2/§4，否則 fork 重建會缺表。
